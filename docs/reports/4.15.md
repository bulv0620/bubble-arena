# 4.15 敌方掩体血条与复活后操作冻结

状态：implemented，待人工玩法/视觉验收。2026-10-15。未Git提交/推送，不进入下一阶段。

## 原因与改动

用户补充“倒计时正常，但人物无法移动”。浏览器复现确认敌方复活时持续抛出 `TypeError: Expected rescue data object`：ArenaOpponent将Rapier返回的Vector3类实例直接作为敌人位置传给selectSpawnPoint，违反共享数据的普通对象校验。异常发生在beforePhysicsStep，时钟已推进，但物理步未完成，故人物无法移动。不是玩家方向键被清空。

- 新增 `apps/web/src/player/arenaOpponentRespawn.ts`，ArenaOpponent调用同一复活事务：在适配边界转换为普通{x,y,z}，保留严格校验；重新检查安全点，全阻塞时等待重试。只重置敌方移动、位置与反馈，不清玩家输入或武器。
- `apps/web/src/HUD/OverheadHealth.tsx` 与新增 `opponentHealthVisibility.ts`：旧Html遮挡只检查头顶标签，标签高于墙时可漏出；增加相机到头/身中心的真实地图射线，两条均挡住即隐藏敌方血条和浮字，淘汰与复活等待也隐藏。初始隐藏防闪，明确更新DOM hidden，不依赖3D group.visible；保留既有标签锚点、距离缩放和Html遮挡。传入Three/Rapier坐标同样转为普通数据。
- 新增 `apps/web/src/core/ArenaOpponentRespawn.integration.test.ts` 与 `apps/web/src/HUD/opponentHealthVisibility.test.ts` 共4项回归：真实Rapier类实例/三轮复活/持键移动/跳跃/武器接受射击/每生命积分，全出生点阻塞恢复；标签露出但头身全挡/侧面恢复/低墙露头/忽略sensor与动态角色/淘汰等待隐藏/无效坐标。
- 同步任务卡、索引、STATUS、ARENA_DEMO和COMBAT_HUD。不改伤害、冷却、比赛规则、地图/hash或依赖。

## 人工复验与限制

刷新游戏，创建对抗房间并开始。观察敌人在完整挡墙后不显示头顶条，绕到头/身可见的位置恢复；倒地仍可显示，淘汰和复活等待隐藏。击倒并补刀淘汰敌方，等待5秒复活，全程或复活后持续WASD、空格、1～4及开火；重复三次，确认仍能操作且每次淘汰仅增加一分。

血条本体判断采样头/身中心，极窄轮廓露边不保证显示，低掩体露头和侧向恢复已有几何回归。浏览器三轮复活采用已移除的诊断夹具，正常生产流程完成额外无夹具检查，真人实战仍待用户验收。未制作正式Blender资源、未联机，未创建本轮回退提交/tag。
