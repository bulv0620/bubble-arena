# 比赛状态与计时（4.8）

默认3秒倒计时、300秒比赛、20分上限，共享MATCH_CONFIG单处定义。短局可在后续结算任务作为单机预设提供。

MatchState是纯核心，waiting只接受权威allReady后进入countdown；倒计时不能重复或跳过。以60Hz物理tick及绝对期限计算时间，playing才扣比赛时间。重复/旧tick不改变快照，参数和tick严格校验；finished不可重启，必须创建新会话。

单机LocalMatch只接收开始意图，场景物理子树加载后才可开始；不是正式房间ready协议。等待/倒计时/结束禁止移动跳跃、武器时钟、伤害、救援、复活及泡泡/靶子模拟。镜头保留。Esc或失焦清输入但不暂停已开始的比赛和生命计时。

比赛结束由整帧计分之后的权威结束接口处理；4.9补充时间/比分/平局结算。UI只订阅快照，不拥有计时器或物理循环。原有模块测试可显式不启用比赛门控；浏览器入口始终启用。

## 胜负与结算（4.9）

每帧顺序：MatchState.advance → 生命/伤害/淘汰计分 → 武器命中/泡泡 → 救援完成统计 → MatchState.resolve。resolve只接受已经advance的同一tick，必须传入整个计分批次的最终红蓝比分；不能处理单个击杀就提前结束。任何队达到20分，或playing到300秒结束；同时触发以分数上限为原因。比分高队胜，相等明确平局，无加时。整个结果（原因、胜队/平局、最终比分、结束tick）及玩家统计不可变，不接收客户端胜负/得分声明。

救援次数仅实际RescueProgress.complete成功且生命恢复后增加。记录救援者、目标lifeId/revision，同一完成去重；不增加队伍积分，旧生命/旧版本/异队/自己/finished拒绝。有界8人身份档案保留统计。单机重建队友夹具分配新生命ID以区分独立救援。

等待界面可选标准5分钟20分、时间测试15秒20分、计分测试5分钟1分。开始后不能改上限，测试不直接修改比分。结算释放鼠标/清输入并关闭设置，隐藏仍会承诺复活的生命提示；显示真实统计。本地默认红队只有模拟蓝队伤害来源，红队获胜与同时上限通过纯核心整批测试覆盖，未声称有正式敌人。
