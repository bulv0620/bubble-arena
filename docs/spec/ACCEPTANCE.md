# 验收规范

## 每任务与阶段

实现报告写清实际检查命令与结果，未存在的检查不能标为通过。核心逻辑 Vitest；协议/房间使用独立客户端集成测试；浏览器页面/加载/退出使用 Playwright 和手动步骤。每阶段需回归前一阶段核心路径，并完成用户试玩、阻断缺陷清零和 Git 回退快照。

## V1 必测矩阵

- macOS Chrome/Safari、Windows Chrome/Edge；记录具体稳定版本及设备。Firefox 作为兼容观察，不列首发阻断平台。
- 四个独立游客 2v2：入房、准备、加载、倒计时、击倒、补刀、救援、复活、比分上限/超时、结算、返回、连续重开三局。
- 四把武器×两张地图：遮挡、换弹/空弹、范围效果、出生合法、复活保护、音效与资源释放。
- 非法消息/超速输入、重复开局、满员/密码错误、退出/房主转移、单端/全队断线、刷新重连、进程异常、资源超时。

## 初始性能目标（测试时必须记硬件）

指定一台 Windows 和一台 Mac 的实际可用设备，在阶段 9 记录 CPU/GPU/RAM、系统和浏览器版本。固定 1920×1080、中画质、DPR 上限 1.5，2v2：中位帧率 ≥60、P95 帧耗时 ≤25ms；不满足则调优或修订支持设备范围，不凭空标通过。

服务端 2v2 单局 P95 tick 耗时 <8ms，服务器 CPU/内存/每客户端上下行量实测记录。客户端下行初始预算 <100KB/s、上行 <30KB/s；资源核心冷加载压缩体积 ≤20MB，20Mbps 测试链路进入地图 ≤15s。连续五局退出后对象计数/内存无持续单调增长，记录测量方法。

网络档：RTT 30/100/200ms，额外抖动 0/20/40ms；使用代理或 OS 网络整形记录工具与参数。WebSocket 丢包测试通过底层 TCP 丢包/断链模拟，不能假装应用消息丢弃等同实际链路。低/中延迟不得出现权威比分/生命不一致；高延迟记录延迟与校正，不承诺与本地相同。V1 历史回溯须独立验证近墙与时间伪造。

## 部署

单区域单实例，静态前端 + 常驻 Colyseus 进程，Docker、反向代理 HTTPS/WSS、健康检查。选目标玩家区域再决定供应商和预算；环境变量管理允许源与端口。公网联机前需决定域名、区域、费用与访问权限，并验证跨网络整局。当前不购买域名/开通云资源。
