## 最小接口与复用边界

- **页面**：复用4.13布局/生成资源/组件、加载与错误出口。6.2负责接连接状态和适配数据，不重新制作视觉。页面提交创建/加入/配置/ready/start等意图，房间只显示服务端快照；不能把现有本地reducer整体升级成权限或物理权威。
- **身份**：5.4建立稳定playerId/重连凭据与临时sessionId的边界，6.1接昵称显示；5.15完善比赛内15秒重连。昵称不做身份凭据。
- **房间**：Lobby发布可加入Party摘要；Party持成员/队伍/准备/配置及比赛关联；Match持权威模拟。6.10先做启动事务、唯一matchId/配置版本、短期准入与无模拟容器骨架，5.5接静态玩家，后续逐卡装配移动/战斗；不让6.10提前写完整物理。
- **两种准备**：6.9是大厅准备意愿，6.11是资源/版本loaded确认。6.10通过不代表开始计时；只有服务端确认全员loaded才倒计时。加载失败/30秒超时撤销准入、回Party清准备和回收Match。
- **内容能力**：服务端发布实际支持的地图、队伍规模与武器ID；房间只能选择其支持集合。四席位配置并不代表5.17已验收；本地四武器/练习照常保留。6.8先做服务支持的配发槽位/规则同步，7.9验证正式四武器资源/数据集成；沿用4.14四枪固定栏与1–4/滚轮，不重建选枪UI或恢复旧两槽/单枪限制。
- **机器人与练习**：当前自动教练属于明确的本地模拟入口；联网房间必须有真实成员，不能静默塞入本机机器人假装第二玩家。正式服务器AI不作为本轮计划前置；将来若要在联网房间补机器人，单列服务端权威AI任务。旧靶场保留独立本地练习，不用它验收多人共享世界。
- **返回与异常**：5.15负责比赛连接/生命/输入，6.12负责Match结束到Party的稳定返回，6.13整合房主迁移、空房、加载回滚、服务重启等跨容器异常。分工不同，验收不重复记完成；M1不宣称完整M2房主异常已通过。
