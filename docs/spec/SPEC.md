# Bubble Arena 完整实施方案

版本：推荐实施基线 V1.1 / 2026-10-08。文档内的玩法选择是本次方案默认值，用户可覆盖；尚未经试玩锁定。技术库版本在各任务首次安装时验证并锁定。

## 产品定位与交付

PC 浏览器、键鼠、原创低模卡通第三人称团队射击。游客无需账号进入大厅，创建/加入房间，选择红蓝队、武器、准备，由房主开始；资源加载、3 秒倒计时、比赛、结算、回原房间。

主要模式 2v2 团队淘汰积分赛；1v1 使用同一生命规则用于联机验证。以救援制造协作和反转。V1 不做回合制、排位、商城、装备成长、语音、账号数据库、AI 对手、移动端或破坏场景。

## 功能边界

- 昵称 2～16 Unicode 码点，去首尾空白，允许中英文、数字、下划线；不允许控制字符/HTML；重名合法，session/player ID 区分。
- 房间名 2～24 码点，人数模式 1v1/2v2，密码可选 4～16 字符；列表不泄露密码。密码由服务端哈希保存，仅用于准入，不作为玩家身份凭证。
- 房主选择地图与 5 分钟/20 分默认规则（测试可配）；成员各选一把主武器并固定携带泡泡副武器。准备后修改队伍/武器取消本人准备，房主改地图/比赛规则取消所有准备。
- 两队均有玩家且人数相等，全体准备（包括房主）后才能开始；1v1 恰好两人、2v2 恰好四人。无旁观者与中途新玩家加入。
- loading 30 秒超时：退出或超时成员移除，所有人返回房间并取消准备；不以缺席人数强行开局。资源错误有重试和退出入口。
- 结算展示比分、胜负、淘汰/助攻/救援数，5 秒后可返回或主动返回原房间。保留地图/武器/队伍，清空准备和比赛临时数据。
- Esc 打开设置面板并释放鼠标；点击“返回游戏”重新请求鼠标锁定。面板含鼠标速度、重置训练、返回游戏；面板屏蔽操作输入，已接受动作计时继续。失焦清空移动/开火/交互输入，保持联网但不会自动暂停比赛。
- 设置保存本地：灵敏度、画质、主/BGM/SFX 音量。每次进入会话必须重新获得浏览器音频用户交互许可。

## 默认操作

WASD 只控制平移，人物始终跟随准星水平朝向，Space 跳跃，鼠标转向，普通武器无右键瞄准效果（狙击开镜后续实现），左键射击，R 换弹，E 长按救援，Esc 打开设置。V1 无冲刺、蹲伏、近战；用户3.14授权主/泡泡副武器用1/2切换。步枪/霰弹/泡泡允许腰射；狙击也可腰射但散布大。

## 内容与资产

一个原创角色基础体，红蓝材质/轮廓标识；同一骨骼支持待机、跑、跳、落地、举枪、射击、换弹、倒地、救援。四把武器为独立 Blender 模型。小镇是首张核心地图，海滨为第二张，竞技场后置。先在白盒验证路线与掩体，再在 Blender 上制作正式视觉，不提前用美术掩盖碰撞问题。

## 工程路线

React/TS/Vite + Three/R3F/Drei；客户端和 Node 服务端使用一致 Rapier 版本和碰撞数据。Colyseus 提供房间和权威模拟。Zustand 只保存低频 UI，音频 Howler/Web Audio。pnpm workspace、Vitest、Playwright。无 NestJS/MySQL/Redis 前置依赖。

先单机建立可复用模拟接口；阶段 5 将输入和规则交给服务器，同一 game-core 用于本地预测，不重新实现一套独立战斗逻辑。武器与生命状态参数集中配置。60Hz tick、20Hz 广播作为初始参数，延迟补偿详见 NETWORK.md。

## 验收与发布

每阶段提供可重复步骤、异常路径、typecheck/build/相关测试和 Git 回退快照。试玩由用户确认。V1 必须完成四客户端 2v2、四武器×两地图、重连和加载失败、不同网络整局。性能测试设备与数值详见 ACCEPTANCE.md；初始预算可在记录测量后调整。

## 尚需实测的事项

美术风格首轮样稿、移动/后坐力与武器平衡、出生点公平性、性能预算、延迟补偿窗口、公网服务区域与部署成本。它们不阻止工程起步，但在对应里程碑前必须留下结论。完整规则见 GAME_DESIGN.md，决策差异见 DECISIONS.md。

## 状态转换约定

| 容器 | 转换 | 异常出口 |
| --- | --- | --- |
| PartyRoom | waiting → loading → playing → finished → waiting | loading 失败回 waiting；空房解散 |
| MatchRoom | waiting → countdown → playing → finished → disposed | 入场失败/服务异常 abort → disposed |
| 玩家 | normal → downed → eliminated → respawning → normal | downed 救援回 normal；finished 停止生命转换 |

资源由 web 预加载并回报 ready，服务端收到所有 ready 后进入 countdown。ready 不能让客户端自行跳过倒计时。loading 与比赛计时分离，比赛时间从 playing 起计算。玩家复活等待已定义为淘汰后的 5s，respawning 是选点/重置的瞬时事务，不额外等待。
